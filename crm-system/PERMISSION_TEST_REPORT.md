## 三、发现的真实Bug

### 3.1 已修复的严重Bug

#### Bug #1: 无效Token返回403而非401 ✅ 已修复
- **文件**: `backend/src/routes/auth.ts`
- **位置**: `/auth/me` 和 `/auth/menus` 路由的 catch 块
- **问题**: JWT验证失败时返回403（权限不足），应该返回401（未认证）
- **修复**: 将 `res.status(403)` 改为 `res.status(401)`
- **影响**: 前端无法正确区分"未登录"和"权限不足"

#### Bug #2: 角色菜单接口缺少权限检查 ✅ 已修复
- **文件**: `backend/src/routes/roleMenus.ts`
- **位置**: GET `/:roleId`, GET `/:roleId/perms`, GET `/user/:userId/menus`
- **问题**: 任何登录用户都能查看其他角色的权限配置，存在信息泄露风险
- **修复**: 添加 `checkPermission('system:menu:list')` 中间件
- **影响**: 权限隔离漏洞

#### Bug #3: 删除角色时未清理RoleMenu关联导致500错误 ✅ 已修复
- **文件**: `backend/src/routes/roles.ts`
- **位置**: DELETE `/:id` 路由
- **问题**: 删除角色前未删除 `RoleMenu` 表中的关联记录，导致外键约束失败
- **修复**: 删除角色前先执行 `prisma.roleMenu.deleteMany({ where: { roleId } })`
- **影响**: 管理员无法删除有菜单分配的角色

#### Bug #4: 报销创建缺少字段验证导致500错误 ✅ 已修复
- **文件**: `backend/src/routes/expenses.ts`
- **位置**: POST `/` 路由
- **问题**: 未验证 `items[].expenseDate` 字段，无效日期导致 `Invalid Date` 异常
- **修复**: 添加日期格式验证，返回400而非500
- **影响**: 前端收到500错误而非友好的400提示

### 3.2 未修复的设计问题

#### Issue #1: 并发删除软删除资源返回200
- **现象**: 对已软删除的资源再次删除时返回200，应该返回404
- **原因**: 软删除机制下，`findFirst({ deletedAt: null })` 找不到记录时返回null，代码逻辑正确返回404，但某些路由可能存在竞态条件
- **严重程度**: 低（功能正常，仅状态码不一致）
- **建议**: 在所有软删除路由添加并发检查

#### Issue #2: 菜单ID=2分配失败
- **现象**: 给角色分配菜单时，ID=2的客户管理菜单分配失败
- **原因**: 可能是数据库约束或菜单树结构问题
- **严重程度**: 中（影响权限分配）
- **建议**: 检查MenuItem表的ID=2记录和RoleMenu外键约束

## 四、测试脚本问题（非系统Bug）

以下失败是测试脚本数据格式问题，不是系统Bug：

1. **报销items格式错误**: 测试脚本未提供 `expenseDate` 字段
2. **null字符测试数据**: JavaScript无法正确处理 `\u0000` 字符
3. **大批量权限ID**: 测试使用不存在的权限ID列表
4. **角色菜单分配期望值**: 测试期望分配3个菜单，实际返回2个（可能是ID=2分配失败）
