## 1. Docker 镜像打包部署到群晖
- **问题**：群晖上运行的是 8月4日 的旧镜像，本地有很多修改未打包
- **解决**：使用 `docker buildx build --no-cache --platform linux/arm64` 强制重新构建
- **打包文件**：
  - `backend.tar` (684MB) - 后端镜像
  - `frontend.tar` (26MB) - 前端镜像
- **部署流程**：
  1. 上传 tar 文件到群晖 `/volume1/docker/crm-system/build/`
  2. SSH 登录群晖执行 `docker load -i <tar文件>`
  3. `docker-compose -f docker-compose.synology.yml restart`
  4. `docker exec -it crm-backend npx prisma db push` 同步数据库

## 2. 数据库迁移处理
### RoleModel.roleKey 字段
- **问题**：新增必填唯一字段，群晖有 6 条数据
- **解决步骤**：
  ```sql
  -- 1. 先添加列（允许为空）
  ALTER TABLE "RoleModel" ADD COLUMN IF NOT EXISTS "roleKey" VARCHAR(255);
  -- 2. 填充数据（用 name 字段值）
  UPDATE "RoleModel" SET "roleKey" = name WHERE "roleKey" IS NULL;
  -- 3. Prisma 会自动添加 UNIQUE 约束
  ```

### Project.progress 字段
- **问题**：Prisma 要删除此字段，但提示有 9 条数据
- **数据内容**：9 个项目的 progress 值都是 0
- **决定**：确认删除（字段已废弃，项目状态改用 status 字段管理）
- **安全措施**：先备份完整数据库 `pg_dump --inserts > backup.sql`

## 3. Bug 修复：客户列表权限问题
- **问题**：`OrgTreeSelect` 组件调用 `/tree` 接口，需要 `crm:organization:list` 权限
- **现象**：没有权限的用户看不到客户下拉列表
- **修复文件**：`frontend/src/components/OrgTreeSelect.tsx`
- **修复方案**：改用 `getOrganizationsSimple()` 接口，无需权限
- **影响页面**：项目列表筛选、销售列表筛选、商务旅行列表筛选等

## 4. Bug 修复：团队成员添加失败
- **问题**：添加成员时的重复检查没有排除软删除记录
- **现象**：移除成员后再次添加会报错"该成员已在项目团队中"，但刷新看不到
- **修复文件**：`backend/src/routes/projects.ts`
- **修复代码**：
  ```typescript
  // 修改前
  const existing = await prisma.projectTeamMember.findFirst({
    where: { projectId, userId: parseInt(userId) }
  })
  // 修改后
  const existing = await prisma.projectTeamMember.findFirst({
    where: { projectId, userId: parseInt(userId), deletedAt: null }
  })
  ```

## 关键经验教训
1. **打包前检查**：确保所有本地修改已保存，使用 `--no-cache` 强制重新构建
2. **数据库迁移**：
   - 新增必填字段时，需要分步处理：先允许为空 → 填充数据 → 添加约束
   - 删除字段前备份数据，确认字段是否真的废弃
3. **权限设计**：下拉列表等基础数据接口应该设计为无需特殊权限
4. **软删除逻辑**：查询、检查时都要记得排除 `deletedAt: null` 的记录
