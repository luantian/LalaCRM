### 技术要点
- dayjs timezone 插件：`dayjs.tz(date, tz)` 解析日期字符串为指定时区，`dayjs().tz(tz)` 转换当前时间到指定时区
- `getUTC8Local()` 的问题是 `.add(8, 'hour')` 改变了实际时间戳而非只是时区显示
- 出差自动打卡在 GET 请求中做写入操作虽不 RESTful，但是最实用的"懒加载"方案

### 日期分界修复（凌晨打卡归错日期）
- **问题**：`DAY_BOUNDARY_HOUR = 5`（凌晨5点分界）导致 0:00-5:00 打卡被归到前一天，但 period 用 `hour < 12` 判断为 MORNING，结果前一天的记录里多了一条凌晨的 MORNING 打卡
- **修复**：`DAY_BOUNDARY_HOUR` 改为 0（自然日分界），凌晨0点后即新的一天
- **加班跨天处理**：`overtime/end` 已有 fallback 查昨天记录；`overtime/start` 新增检查昨天未结束加班；`GET /today` 新增查昨天活跃加班记录
- **数据修复**：2 条历史记录 checkInDate 与 checkInTime 实际日期不匹配，已修正

   - `utils/permission.ts`：管理员判断用 `user.role === 'ADMIN'`
   - `hooks/usePermission.ts`：管理员判断用 `permissions.includes('*')`
   - `routeConfig.ts canAccessRoute`：管理员判断用 `user.role/roleKey === 'ADMIN'`
   - 后果：若用户有 `*` 权限但 role 不是 ADMIN，不同组件表现不一

   - 外层组装 children（241行）未应用 contracts 过滤，也未过滤 key
   - path 计算用多重三元（229行），空字符串 falsy 会走错分支

5. **usePermission 缓存问题**
   - `useState(readPermissions)` 仅 mount 时初始化，依赖事件刷新
   - Login.tsx 写了独立的 `permissions` key 但从未被读取（冗余）

#### 设计问题（建议优化）
